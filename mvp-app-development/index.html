The hard part is what to leave out

Most MVPs I’m asked to quote are really version three. Five user types, a chat, a marketplace, an admin panel with twelve reports. It all matters eventually. Not in month one.

So the first call is about the one flow a user must be able to finish on launch day, and who that user is. Everything else goes on a list for later. That list is often where the second contract comes from, once real users show what they need.

What’s in an MVP

  • An iOS and Android app from one React Native codebase.
  • A web dashboard for your team.
  • The backend and database: Supabase with row-level security, or Node.js with PostgreSQL.
  • Sign-in, payments or subscriptions (Stripe, RevenueCat), and push notifications.
  • Store listings, a release pipeline and your first App Store and Play releases.

Questions founders ask

How much does an MVP app cost?

From $3,000 for a focused first version. The biggest cost driver is scope, which is why the first call is about what to leave out.

How long does it take to build an MVP?

A tightly scoped MVP takes weeks. A platform with video, payments and an admin side takes a few months: Baba Telehealth was scoped at 14 weeks.

Which tech stack do you use for MVPs?

React Native with Expo for iOS and Android, React for the web admin, and Supabase or Node.js with PostgreSQL behind them. It’s a stack I’ve shipped many times, and it grows with you: Gold Minds runs on it for 2,000+ students.

Can you build the web version too?

Yes. Most MVPs I build have a mobile app for users and a web dashboard for the team running the business.

What happens after launch?

We look at what users actually do, fix what breaks, and plan the next version. That work is billed hourly or as a scoped phase.
