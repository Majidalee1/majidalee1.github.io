Developer's Notes

How I build software

  • On cloud cost

    Read the bill as a diagram.

    A cost breakdown shows where your design disagrees with your traffic. It's usually more honest than the architecture diagram.

  • On change

    Migrate, don't rewrite.

    Move one piece, prove it under real traffic, then move the next. Every migration I've run stayed live.

  • On AI

    The tools are the product.

    Give a model narrow tools and make it look before it acts. That's API design, not prompt writing.

  • On agents

    Give failures an address.

    Seven agents aren't smarter than one prompt, but you can tell which one broke. The safety check lives inside the graph.

  • On mobile

    Offline is a feature.

    People use apps in basements, clinics and on bad networks. Design the sync first and the screens second.

  • On honesty

    Claim what survives a follow-up.

    If a team built it, I say team. If I contributed, I say contributed. Ask me about any line on this page.

Multi-agent AI

Seven agents, one safety gate.

Where
Myaigi, through Codenetic
Role
Architect; teammates implemented parts
Stack
LangGraph, Pinecone, Cassandra, SSE
Models
Claude, OpenAI, Gemini

A coaching product has to do several different jobs: understand the request, remember the person, plan, schedule and coach. Putting all of that behind one long prompt makes every feature a little worse, and when the answer is wrong there's nowhere to look.

So an intent router sends each request to the right specialist agent in a LangGraph graph. Pinecone holds what the coach remembers about a person; Cassandra holds the facts, like which plan they're on, because those must never be fuzzy. Answers stream to the app over Server-Sent Events.

The decision I'd defend hardest: a QA agent checks every answer before it leaves, and it lives inside the graph. No new client or shortcut can route around it. It costs some latency; for personal coaching, that trade isn't close.
AI tooling

Ask the database in plain English.

Where
Sehat Kahani
Role
Built it alone
Stack
Python, MCP, Chainlit, Azure MySQL
Status
In use internally

Every operational question at a telemedicine platform, like consult counts per clinic or a tenant's real configuration, lived in the production database, and only people fluent in the schema could answer them.

This Model Context Protocol server gives an LLM a few narrow tools: list tables, describe a table, run a read query. The model has to look before it acts, which produces far better queries than a raw SQL escape hatch. A Chainlit chat window gives ops staff a place to ask.

What I'd change on the next deploy: credentials in a managed secret store, read-only enforced at the connection, and result caps with timeouts in the server. Models are cooperative, not reliable.
Cloud cost

Same platform. 88% cheaper.

Where
Zetsol, 2021–2022
Role
Individual contributor
Before
About $12,000 a month
After
About $1,500 a month

A national telemedicine platform was sized for peak load every hour of the day. The bill was the symptom; the real problem was that the shape of the infrastructure no longer matched the shape of the traffic.

Three moves: one Application Gateway as the single entry point, right-sized App Service plans for requests, and consumption-billed Azure Functions for everything that runs on a trigger. That last one saved the most.

Patients were using it throughout, so it moved one workload at a time, with the old path kept until the new one proved itself. The lesson I still use: the cheapest compute is the compute that isn't running.
React Native

Works where the signal doesn't.

Where
Brevity care app, through Codenetic
Role
Team delivery, two engineers
Stack
React Native, SQLite, TanStack Query
Users
Care staff in the field

Care workers log visits in basements, rural homes and hospital corridors. An app that shows a spinner without a signal is an app they stop using.

Everything is written to a local SQLite store first and queued. When the connection comes back, a background sync sends the queue and resolves conflicting edits, with a clear status so staff always know what has been saved and what has synced.

Designing the sync first and the screens second is now how I start every mobile project.
Distributed systems

One scan. Every service hears it.

Where
Leafgistics, through BitsPro
Role
Backend and DevOps team lead
Stack
Node.js, NATS Streaming, EKS, Fargate
Scale
3 fulfilment centres

In a regulated US warehouse, one physical action, like a pallet moving, changes inventory, orders and the audit record at once. And every change has to be provable.

We modelled that as one event on a NATS Streaming bus that independent Node.js services react to. The audit trail is a real consumer, not a logging afterthought, and a slow service never blocks the warehouse floor. Services ran on EKS and Fargate so four engineers spent their time on the domain, not on servers.

I also moved warehouse search from Redshift to ClickHouse across three sites: cheaper, and just as fast on the screen operators use all day.
React Native

App calls that ring like real ones.

Where
Tryst Africa, through Codenetic
Role
Team delivery
Stack
React Native, CallKit, Android Telecom, VoIP push
Also
In-app subscriptions

In a social app, a call that only rings while the app is open is a missed call. Users expect the lock screen, the ringtone and the green button.

The work wired the video and voice SDK into iOS CallKit and Android's Telecom stack with VoIP push, so incoming calls show up in the phone's own call screen, and answering or declining there drives the app's call state.

Alongside it: a hybrid real-time setup with a separate Cloudflare-backed chat service, and in-app purchase flows for subscriptions.
